# 老电视兼容：Tizen 6.0、Tizen 5.5

> 这是 [CLAUDE.md](../CLAUDE.md) 指过来的专题。上面「结论」是现在成立的；下面是前因后果和测量记录，按当时的样子留着，日期是那天的。

## 结论

- **最低 Tizen 5.5（Chromium 69）**。5.0（Chromium 63）做不了：mtcute 用 BigInt（67 起），是语法、降不了。
- 语法：`build/bundle.sh` 的 esbuild target 跟着 `required_version` 走；`tools/syntax-verify.mjs` 对着那代引擎查每个脚本（`node --check` 看不出来）。
- API：`build/src/compat.js` 补（AbortSignal 的 reason / throwIfAborted / any，globalThis、Object.fromEntries、queueMicrotask、TextEncoder.encodeInto、Symbol.description），`test/compat.mjs` 卡着。
- mtcute 的 wasm：用 binaryen 降成 MVP（Chromium 75 才认非陷入的浮点转整数），降不干净就不打包。
- 桌面上测老引擎：Chromium 快照（69 = 576753）+ 裸 CDP（Playwright 驱动不了）；开源 Chromium 没有 H.264 / AAC。
- **Tizen 5.5、6.x 的电视上都还没跑过**，等诊断日志。

### Tizen 6.0 上打不开（2026-10-23，别人电视的诊断日志）

两台 Tizen 6.0（Chromium 76）的电视装 1.1.2，每次启动都是「Uncaught SyntaxError: Unexpected token ( @tg.bundle.js:1」，接着
「TGLib is not defined」（其中一台一分钟里重开了十来次）。`config.xml` 从骨架起就是 `required_version="6.0"`，esbuild 却一直是 `--target=chrome120`。
- 1.1.2 的包里比 Chromium 76 新的写法：私有方法 `#m()` 11 处（84 起认；第一处是 @fuman/utils 的 `BufferPool` 的 `#realloc()`，报错的就是它
  后面那个 `(`）、`??` 458 处、`?.` 389 处（80 起）。`node --check` 看不出来，开发机的 node 什么都认。
- **语法**：`build/bundle.sh` 一处打包（deploy / release 共用），target chrome76，包大 1.5%（2.81 → 2.85MB）。`tools/syntax-verify.mjs` 用 acorn
  解析包里每个脚本和后台线程那份文本，对着「从哪个 Chromium 起认」的表查，比 required_version 那代新就拒绝 —— 对 1.1.2 的包报出上面三样，对新包通过。
- **API**（esbuild 降不了，`build/src/compat.js` 补；在打出来的包里一个个 grep 过）：`AbortSignal.prototype.throwIfAborted`（100 起）—— @fuman/net 连 WebSocket
  之前就调，没有它**连不上 Telegram、不报错、一直等**；`signal.reason`（98 起）—— 没有它被取消时抛出去的是 undefined；`AbortSignal.any`（116 起）——
  重试时合并信号。Tizen 6.5–7.0（Chromium 85–94）解析得了 1.1.2 的包，按这个推断卡在连 Telegram 那一步（没有那几代电视的日志）。
- **桌面 Chromium 76.0.3809 实测**（快照 665002，Rosetta）：1.1.2 的包报的就是电视上那句（`1:2406`）；新包解析得了、`TGLib` 在、二维码出得来，
  后台线程 1.5 秒连上 Telegram、回 `AUTH_KEY_UNREGISTERED`（还没登录，就是连上了）；同一份包去掉 throwIfAborted 那段补丁，`getMe` 20 秒没回。
  后台线程要从 localhost 起：桌面上从 `file://` 起的 blob worker 没有 `crypto.subtle`（电视上页面和线程都是安全上下文，没这个问题）。
  **Tizen 6.0 的电视上还没跑过** —— 那两台装上新版之后的诊断日志会说。
- **壳没换号**：`tg.bundle.js` 不随更新下发，按规矩该 `SHELL` 1 → 2，没加，`update/shell.json` 里 shell 1 的指纹改成了新包的。加一的话，Tizen 9 上
  正常用的电视以后全都收不到更新、要重装；不加，收到 1.1.3 更新包的电视和现在比什么都没变（`app/js` 不依赖新包里的任何东西），而 Tizen 6.x–8.0
  要的语法和补丁在新包里，只能重装 wgt 拿到，加不加都一样。打包参数原来不在 `vendorPrint()` 里（只改 `--target` 拦不住），现在 `bundle.sh`、
  `compat.js` 都算进去。
- **自动更新换不了 mtcute，屏幕上就照直说要重装**（1.1.5）：那几代电视照样自动更新到新代码，`tg.bundle.js` 还是 1.1.2 的，`TGLib` 不存在 ——
  原来走到「连不上 Telegram，检查网络后按确认重试」，看着像网络问题。现在 `boot()` 一开始就查，`要重新安装一次`（用 Apps2Samsung 再装一次
  最新版），日志 `mtcute 没加载起来（TGLib 不存在；装的 …，跑的 …）`、报一次出事（数得出还有几台卡在旧包上）。两个启动失败的界面都走
  `bootFail()`，右边二维码那块空白藏起来。桌面上拦掉 `tg.bundle.js` 看过中英文两版；电视上正常启动不受影响。
- **包解析得了、却是 1.1.3 以前打的，也要重装**（10-24）：一台 Tizen 8.0（Chromium 108）装的 1.1.2、跑的 1.1.5，`TGLib` 在，连得上、登得进、
  列得出视频，每一次下载都是 `AbortSignal.any is not a function`（Chromium 116 才有，旧包没补），90 秒没画面、只说放不了，放弃之后还在每 10 秒重试。
  新包的 `compat.js` 在主线程也补，所以 `boot()` 在主线程看见 `AbortSignal.any` / `throwIfAborted` 缺着，就是包是旧的：同一个「要重新安装一次」，
  日志 `安装包里的 mtcute 用不了（这台电视没有 AbortSignal.any，包里也没补；…）`，出事的文字不变（照样数得出几台）。Chromium 116 以上不受影响。
  90 秒放弃的时候把这个视频的下载停掉。

### Tizen 5.5（2026-10-26，issue #2「Support for tizen OS v5?」）

诊断日志里一台巴西的 Tizen 5.5（UA `Tizen 5.5 … 69.0.3497.106`）10-25 装上了 1.1.7（`required_version` 是 6.0，它也装上了），
有人在上面一步步改包往前推：先「Unexpected token =」（class fields，Chromium 72）→ 降了语法之后「Object.fromEntries is not a function」
（73）→ 补了之后卡在 mtcute 的 wasm：「Compiling wasm function #58:deflate_compute_true_cost failed: Invalid opcode (enable with
--experimental-wasm-sat_f2i_conversions)」（非陷入的浮点转整数，Chromium 75）。
- **Tizen 5.0（Chromium 63）做不了**：mtcute 包里 246 处 BigInt 字面量（`0n`、`1n`…），BigInt 67 才有，是语法、降不了也补不上。
- **5.5 的做法**：`config.xml` 的 `required_version` → 5.5；`build/bundle.sh` 的 target → chrome69；`compat.js` 补 globalThis（71）、
  Object.fromEntries（73）、queueMicrotask（71）、TextEncoder.encodeInto（74，mtcute 写 TL 字符串用）、Symbol.description（70）；
  **wasm 用 binaryen（build 的 devDependency，钉 123.0.0）降成 MVP**：`--llvm-nontrapping-fptoint-lowering --signext-lowering
  --llvm-memory-copy-fill-lowering`，降完 `--mvp-features` 校验不过就不打包。只降不带 SIMD 的那份（带 SIMD 的只在 91 起的引擎上用）。
  降过的和原版 sha256 / sha1 / IGE / CTR / 压缩 / 解压逐项一致（57KB → 51KB）。`--all-features` 会让 memory.copy 的降级报
  「Memory64 and multi-memory not supported」，要一样样列。
- **桌面 Chromium 69 实测**（快照 576753 = 69.0.3497.0，Rosetta）：Playwright 驱动不了这么老的，用裸 CDP（`/json/new` 建页面，
  Runtime / Page 域）；无头模式渲染进程一启动就崩（Rosetta 下要 `--no-sandbox`）。真的 mtcute、真的 Telegram：后台线程 221ms 连上、
  出登录码；界面（假数据）和新版渲染一样；VP9 的 MKV 放得了、快进得了。H.264 / AAC 测不了 —— 开源 Chromium 不带这两个解码器。
- 壳没换号：`tg.bundle.js` 变了（目标、补丁、wasm），按「只换打包目标、补 API」的例外，`update/shell.json` 里 shell 1 的指纹改成新的。
  5.5 的电视反正要装新的 wgt。**Tizen 5.5 的电视上还没跑过**，等那台巴西电视的诊断日志。
