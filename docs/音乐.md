# 音乐（music.js / flac.js）

> 这是 [CLAUDE.md](../CLAUDE.md) 指过来的专题。上面「结论」是现在成立的；下面是前因后果和测量记录。

## 结论

- 来自 issue #3（「Telegram Music」，2026-10-25）。做成这个应用里的一部分，不另出一个应用：登录、来源栏共用。
- **混排**：Telegram 的「音乐」筛选（`inputMessagesFilterMusic`，带歌名 / 歌手属性的音频文件，不含语音）是 `TG.videos` 合并的第三路；
  只有歌的频道也进来源栏（`videoCount` 视频、当文件发的视频都没有时再问音乐）；搜索也搜。
- **放法：整首下下来，做成 `blob:` 交给 `<audio>`**。电视自己的播放器对 blob 的 MP3 / M4A / Opus / WAV 都放得了、跳得动；网上的 MP4 给
  `video.src` 却不可靠（见 [网页链接.md](网页链接.md)），所以不走「直接给地址」。放着这首就把下一首下好，内存里最多留 3 首。
- **FLAC 电视解不了**，哪条路都不行（下面的表）。音乐里的 FLAC 用 `flac.js` 自己解：边下边在后台线程里解成 16 位 PCM，拼成 WAV 再交给 `<audio>`。
  电视上解码约实时的 21 倍：3 分钟 CD 音质（18MB）下完又等 6.6 秒，从按键到出声 10 秒；之后的歌预先下好、解好。
- 视频里的 FLAC 音轨（MKV / MP4）在电视上当放不了（player.js 的 `audioOk`），不然会一直卡在「正在打开」。
- 界面：卡片是方形专辑图（Telegram 给的缩略图）放在同一张图缩小拉伸的底上；音乐画面左封面右歌名、歌手、来自哪个群、下一首；
  确认暂停、←→ 10 秒、↑↓（遥控器的上一曲 / 下一曲）换歌、返回回列表**接着放**（卡片上标「♪ 正在放」，点它回到画面不重放）、停止键停。
  放视频时歌停；切到别的应用时暂停。
- 放不起来也不报错的（以前的 FLAC 就是这样）12 秒不走算放不了，3 秒后放下一首；连着 5 首放不了就停。
- **ALAC（Apple 无损）的 m4a 电视解不了**（2026-10-27 诊断日志：一串 40 首里的一首 68MB、5 分半，`<audio>` 只报
  `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`，屏幕上是这句原话、还当出事传了上来）。app 下的时候看 moov 里的音轨（`m4aProblem`，用 mp4.js 的
  `parseMoov`），解不了就说「Apple 无损（ALAC）音频电视解不了」、3 秒后放下一首，不当出事；moov 在开头的头两块（1MB）到了就知道、不用下完，
  在末尾的下完才知道。要放的话得像 FLAC 那样自己解（ALAC 有开源解码器），还没做。
- **还没做**：离开应用后台播放（Tizen 的网页应用挂到后台就停）；随机 / 单曲循环；歌词。

## 电视怎么放音频文件（2026-10-26，`deploy.sh --music`，参考机 Tizen 9）

测试文件在这台电脑上（`test/media/music/`，`test/serve.mjs` 给），电视从局域网取。

| | `<audio>` + blob | `<audio>` + http 地址 | 跳到中间 |
|---|---|---|---|
| MP3 | ✓（下载完 0.5 秒出声） | ✓ | ✓ |
| M4A（AAC） | ✓ | ✓ | ✓ |
| Opus（OGG） | ✓ | ✓ | ✓ |
| WAV | ✓ | ✓ | ✓ |
| FLAC | ✗ 不报错、播放头不动 | ✗ | — |
| FLAC 装进 MP4 | ✗ | ✗ | — |

`canPlayType` 对 FLAC 说 probably。再用 MSE 对照（整个分段 MP4 一次 append）：

| MSE | 结果 |
|---|---|
| AAC，只有音频 | ✓ readyState 4 |
| AAC + 640x360 黑画面 | ✓ |
| FLAC，只有音频 | ✗ 数据全进去了（0–40 秒），readyState 停在 1 |
| FLAC + 640x360 黑画面 | ✗ 一样 |

`isTypeSupported('audio/mp4; codecs="flac"')` 是 true。所以不是「只有音频」的问题，是这台电视根本不解 FLAC。
（第一次配视频用的是 64x64 的黑画面，连 AAC 那个对照都出错、MediaSource 被关 —— 硬件解码器不收这么小的画面。）

## flac.js

按 RFC 9639 写：帧头、CONSTANT / VERBATIM / FIXED / LPC 子帧、Rice / Rice2 余数（含 escape）、wasted bits、三种声道还原。
16 位以上的右移成 16 位（和 ffmpeg 解成 s16 一样，不加抖动），以下的左移；采样率、声道数照原样。不校验 CRC、MD5。
LPC 用浮点累加（系数乘样本最多 2^40，32 阶加起来不到 2^46，2^53 以内是准的），再除以 2^shift 向下取整。
字节不够时从帧头重来，帧头不对往后找下一个 0xFFF8 / 0xFFF9。STREAMINFO 写了最大帧长就攒够它再解，没写攒 1MB。

后台线程的脚本是 `core` 函数的源码拼上收发消息的几行，用 `blob:` 地址起（电视上页面是 `file://`），所以 `core` 不能引用外面的东西。

`test/check-flac.mjs` 用 ffmpeg 生成 13 种（压缩级别 0 / 5 / 12、24 位、单声道、三种声道还原、只用固定预测、帧长 1152、6 声道、很小的音量），
解出来的 PCM 和 ffmpeg 解的逐字节一样；桌面上 100–200 倍速。

## 自测

`zsh tools/deploy.sh --music`（先开 `RATE=0 LAT=0 node test/serve.mjs`）：一串假的歌（MP3、3 分钟 FLAC、M4A），数据从这台电脑取，
TG.source / thumb 对它们换成 HTTP，走真的音乐画面：MP3 放起来 → ↓ FLAC → 快进 → ↓ M4A → ↑ 回到 FLAC → 返回列表接着放 → 放 ALAC 的 m4a
（`test/media/music/t_alac.m4a`：`ffmpeg -i src.wav -c:a alac t_alac.m4a`）要说电视解不了。
10-26 电视上 7 步全过（MP3 2.5 秒、FLAC 10.2 秒、M4A 1.8 秒、回到解好的 FLAC 0.9 秒）；10-27 加了 ALAC 那步，8 步全过。
